# gh-agentic-workflow

Skills, agents, commands and hooks for AI-assisted development, shared across
Claude Code, Cursor, PI and OpenCode. The source of truth is this repository;
`asset-registry.yml` lists every asset.

There are two ways to install it. Pick one:

| | Plugin (recommended for Claude Code) | `install.sh` (all tools) |
|---|---|---|
| Targets | Claude Code only | Claude Code, Cursor, PI, OpenCode, `~/.agents` |
| Granularity | Per plugin (9 groups) | Everything, copied as-is |
| Updates | `/plugin marketplace update` | `git pull && bash install.sh` |
| Hooks | Shipped with the plugin | Merged into `~/.claude/settings.json` |

## 1. Install as Claude Code plugins

The marketplace is generated by CI on the `dist` branch (never edit it by hand).

```bash
claude plugin marketplace add https://github.com/guilhemheinrich/gh-agentic-workflow.git#dist
```

Then install all ten plugins at once (one copy-paste).

bash / zsh / fish (no `for` loop, so it works in any of them):

```bash
printf '%s\n' agent-sessions agent-tooling audit backend-and-data docker-and-k8s frontend git-and-delivery review-and-projection speckit testing-and-debugging | xargs -I{} claude plugin install {}@gh-agentic-workflow
```

PowerShell:

```powershell
'agent-sessions','agent-tooling','audit','backend-and-data','docker-and-k8s','frontend','git-and-delivery','review-and-projection','speckit','testing-and-debugging' | ForEach-Object { claude plugin install "$_@gh-agentic-workflow" }
```

Or pick only the ones you want:

```bash
claude plugin install agent-sessions@gh-agentic-workflow
claude plugin install git-and-delivery@gh-agentic-workflow
claude plugin install testing-and-debugging@gh-agentic-workflow
```

The same from inside a Claude Code session: `/plugin marketplace add ...`
then `/plugin install <plugin>@gh-agentic-workflow`. Refresh later with
`/plugin marketplace update gh-agentic-workflow`.

Skills and commands are namespaced `/<plugin>:<name>`, for example
`/testing-and-debugging:e2e-playwright` or `/git-and-delivery:push`.

| Plugin | Contents |
|---|---|
| `agent-sessions` | Pilot sessions, session titles, conversation focus, PR/tracker watching, grievances, usage tracking (9 skills, 9 hooks) |
| `agent-tooling` | Plugin release, static-validation hooks, LSP over MCP, ESLint for NestJS |
| `audit` | Evidence-based audits (database, front-end, infrastructure, security) producing a triaged findings report, with open-source tooling run in Docker |
| `backend-and-data` | SQL migrations, pg-boss + Drizzle, OpenAPI client generation, API conversion |
| `docker-and-k8s` | Dockerfile patterns, hot-reload volumes, Compose ports, Kubernetes troubleshooting |
| `frontend` | Lit web components, cursor glow, text clip effects, Starlight live demos |
| `git-and-delivery` | Commits, merges, PR history, CI/CD design, semantic-release, SonarQube |
| `review-and-projection` | Adversarial multi-model review, change/data projections |
| `speckit` | Spec-driven agents (orchestrator, specifier, implementer, tester...). Needs [GitHub Spec Kit](https://github.com/github/spec-kit) installed |
| `testing-and-debugging` | Playwright E2E, auth factory, test targeting, web analysis, scraper |

Plugins cannot see each other's files. A hook that calls a skill script only
works if that skill ships in the same plugin; this is why the session hooks
live in `agent-sessions` together with their skills.

Pin the marketplace for a whole team in `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "gh-agentic-workflow": {
      "source": { "source": "github", "repo": "guilhemheinrich/gh-agentic-workflow", "ref": "dist" }
    }
  }
}
```

## 2. Install with `install.sh` (user level, every tool)

From a checkout of this repository:

```bash
git clone git@github.com:guilhemheinrich/gh-agentic-workflow.git
cd gh-agentic-workflow
bash install.sh
```

On Windows (PowerShell): `.\install.ps1`.

It copies, as plain overwrites:

| Source | Claude Code | Others |
|---|---|---|
| `skills/` | `~/.claude/skills` | `~/.agents/skills`, `~/.cursor/skills`, `~/.pi/agent/skills`, `~/.config/opencode/skills` |
| `commands/` | `~/.claude/commands` | Cursor, PI (`prompts`), OpenCode |
| `agents/` | `~/.claude/agents` | Cursor, PI, OpenCode |
| `hooks/`, `scripts/` | | `~/.agents/hooks`, `~/.agents/scripts` (and Cursor) |

Options:

```bash
bash install.sh --no-claude-hooks   # do not touch ~/.claude/settings.json
bash install.sh --export-mcp        # also export ~/.cursor/mcp.json to OpenCode / Claude Code / Claude Desktop
```

Unless `--no-claude-hooks` is passed, the installer registers the session hooks
in `~/.claude/settings.json` (idempotent merge, existing keys untouched). It
needs Node.js for that step. Re-running it after `git pull` is the update path;
install from the default branch, since the copy overwrites newer files.

## 3. Skills that must live at user level

These skills are driven by hooks that look for their scripts under
`~/.agents/` (for instance `~/.agents/skills/session-title/scripts/session-title.sh`),
so they need the `install.sh` copy even if you use the plugins for everything else:

- `session-title` — keeps the session title equal to the next action owed by the human.
- `session-meta` — per-session metadata (`scope`, `subject`, `role`) read by the other hooks.
- `conversation-focus` — split proposals and closing summary (Stop and prompt hooks).
- `pilot-session` — pilot role; arms the reminder hook through `session-meta`.
- `pr-watch` — the `prw` poller runs from the installed copy.
- `linear-atlas` — the `lw` watcher (and its MCP server), the dependency graph and the semantic check.
- `linear-tracker` — the lifecycle installer and the grievance publish backend.

All other skills work either way.

## 4. Installation and setup skills

This repository has no skill whose only job is to install the workflow; the
installers are `install.sh` / `install.ps1` above. Skills that set something up
on demand:

- `static-validation-hooks` — installs the validation hook template in a consumer repository.
- `linear-tracker` — `install-lifecycle.sh <repo> --team NAME` wires the Linear lifecycle hook in a repository.
- `pr-watch` — `prw daemon start` installs the PR poller.
- `claude-plugin-release` — versioning and local testing of the plugins themselves.

## For contributors

Plugins are generated from `asset-registry.yml` by `scripts/build-plugins.mjs`;
details, grouping rule and naming contract are in
[scripts/plugin-builder/README.md](scripts/plugin-builder/README.md).

```bash
npm ci
npm run build:plugins     # writes dist/ (gitignored)
npm run test:plugins
claude plugin validate dist --strict
claude --plugin-dir dist/plugins/agent-sessions   # try one plugin live
```

Adding or renaming an asset means updating `asset-registry.yml` in the same
change (`make sync-registry` validates it). The `dist` branch is republished by
CI on every push to `main`.
