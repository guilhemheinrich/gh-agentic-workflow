# Grievances — ledger of non-blocking findings

> Committed register of underlying problems, technical debt and improvements met
> **outside the scope of an in-flight spec**: "what works, but will not scale, or
> only holds together with tape". Committed on purpose — friction should
> accumulate visibly.
>
> **This file is maintained programmatically.** Declare and close entries with the
> `grievances` skill CLI; never hand-edit the index tables below:
>
> ```bash
> grievances.py add --short "..." --severity high --locus "file.go:42" \
>   --finding "..." --impact "..." --fix "..." --effort 0.5d
> grievances.py resolve GRV-0001 --commit 1a2b3c4 --note "..."
> ```
>
> Prose under `# Details` is human-owned and kept verbatim; the heading lines, the
> `<!-- grievance:... -->` markers and both tables belong to the tool, which
> re-sorts them chronologically on every mutation.
>
> **Boundary.** Anything regulatory, security-related, data-losing or needing an
> arbitration does NOT stay here: it becomes a spec, or a fiche in the pilot
> `ROADMAP.md`, immediately — close the grievance with `--promoted-to <ref>` so a
> one-line pointer remains and the analysis lives in exactly one artifact.
>
> Never paste a secret, a token or a credential-bearing log line into an entry:
> record the *command* that retrieves a credential, never its value.
>
> When to read and when to write: `specs/CLAUDE.md`.

### GRV-occurrences-counter-loses-1aa4 · medium · 2026-08-26 — occurrences counter loses an increment when two branches both bump

`skills/grievances/scripts/grievances.py:cmd_bump` · declared in spec 015 adversarial review, deferred by design · tags: `grievances`, `merge-safety`

<!-- grievance:GRV-occurrences-counter-loses-1aa4:prose -->

**Finding.** `occurrences` is an int that `bump` increments. Two branches bumping the same grievance from 2 both write 3; the merge keeps one 3, so the true count of 4 is lost. Same class as the identifier collision spec 015 fixed, and untouched by it.

**Impact.** The counter is the ledger's only frequency signal and the tie-breaker for what gets promoted to a spec. Silently undercounting makes a recurring papercut look like a one-off, which is exactly the entry most worth promoting.

**Why the tests miss it.** Spec 015's suite covers identifier collisions across branches; nothing exercises a concurrent bump, because a unit test sees one ledger at a time and the loss only appears at merge.

**Fix.** Replace the integer with an append-only list of recurrence dates, which merges by union rather than by last-write-wins. Also improves the record: when a finding recurred is more useful than how often. **Effort: 0.5d.**
