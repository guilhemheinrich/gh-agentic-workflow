# Feature template: proposal

Workspace-level Linear issue template « Feature ». Applies the Type label
**Feature**. Title prefix: none. Semantics and the test that decides
this type: [`../../references/ticket-types.md`](../../references/ticket-types.md).

User story, acceptance criteria and scope; the tech split goes to linked Technical tasks.

```markdown
## In plain words, with an example

<What the user will be able to do, and one concrete case. E.g. « An invitation sent from the calendar opens as an invite in the client's mail app. »>

## Need

As a <role>, I can <action>, so that <benefit>.

## Acceptance criteria

* [ ] …
* [ ] …

## Out of scope

What this feature does not do.

## Specification

Link to the spec and the date of its current version.

## Design required

Yes or no. If yes, by DD/MM.

## Tech split

Filled in by the devs: the linked Technical tasks, as sub-issues.

## Recommended proofs

One Proof ticket per acceptance criterion that can be observed on staging (a command and its output, or a screenshot), in the lot's milestone.
```
