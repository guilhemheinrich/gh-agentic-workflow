# Improvement template: proposal

Workspace-level Linear issue template « Improvement ». Applies the Type label
**Improvement**. Title prefix: none. Semantics and the test that decides
this type: [`../../references/ticket-types.md`](../../references/ticket-types.md).

For a capability the user already has, made better, with no broken promise behind it.

```markdown
## In plain words, with an example

<What changes for the user, and one concrete case. E.g. « The invoice export, which already exists, gains a VAT column. »>

## Today

What the user already does, and what bothers them.

## After

What they will do: faster, more clearly or more completely.

## Acceptance criteria

* [ ] …

## Specification

Link and version, or « none ».

## Recommended proof

Link to the Proof ticket that will show the change on staging (a command and its output, or a screenshot), or « none » and why.
```
